# T-2026-04-21-02-1 — Validación VirusTotal: certificado de prueba con URL de phishing conocida

**Estado:** completado — 2026-04-21
**Fecha creación:** 2026-04-21
**Asignado a:** LLM ejecutor (tras aprobación del humano)
**Depende de:** T-2026-04-17-03 (threat-check bajo demanda — completada)

## Objetivo

Agregar un certificado de prueba al catálogo cuyo `portal_url` apunta a
`https://www.amtso.org/feature-settings-check-phishing-page/` — URL pública
de AMTSO diseñada específicamente para testear motores anti-phishing. VirusTotal
la debe marcar como `suspicious` o `malicious`. Con esto se valida el flujo
completo: catalog → threat-check → bloqueo de acceso en UI.

## Contexto de seguridad

- La URL **no es un sitio real de phishing**: es una página de prueba oficial
  de AMTSO (Anti-Malware Testing Standards Organization) para validar que los
  motores de seguridad detectan phishing correctamente.
- **No se debe abrir ni visitar** desde ningún navegador durante la ejecución
  de la tarea.
- El backend **solo envía la URL a VirusTotal**, nunca la abre ni descarga
  su contenido.

## Alcance

**Incluye**
- Agregar entrada al catálogo vía script SQL o endpoint admin.
- Validar que threat-check devuelve `suspicious` o `malicious` para esa fila.
- Modificar `CertificateTable.jsx`: si la amenaza es `suspicious` o `malicious`,
  ocultar/deshabilitar el botón "Ir al sitio" y mostrar aviso de bloqueo.
- El aviso debe sugerir contactar a la entidad por teléfono o correo.

**No incluye**
- Modificar la lógica de VT ni el backend más allá de lo ya implementado.
- Bloqueo automático en carga — solo aplica tras revisar amenaza manualmente.
- Persistencia del bloqueo entre sesiones (fuera de alcance de esta tarea).

## Datos del certificado de prueba

```sql
INSERT INTO certificates (
  name,
  issuer,
  purposes,
  portal_url,
  estimated_days,
  is_law_1918,
  observations,
  regex_patterns
) VALUES (
  'Certificado de Prueba Anti-Phishing (TEST)',
  'AMTSO — Anti-Malware Testing Standards Organization',
  ARRAY['prueba'],
  'https://www.amtso.org/feature-settings-check-phishing-page/',
  0,
  false,
  'ENTRADA DE PRUEBA. No usar en producción. Sirve para validar detección de amenazas con VirusTotal.',
  ARRAY['certificado.*prueba.*amtso', 'amtso.*phishing']
);
```

> Alternativa si no hay acceso directo a PostgreSQL: crear la entrada
> vía `POST /api/v1/admin/certificates` con rol admin.

## Cambios en `CertificateTable.jsx`

Cuando `threat.threat_level` es `suspicious` o `malicious`, en la columna
`Portal`:

**Antes (comportamiento actual):**
```jsx
<a href={cert.portal_url} target="_blank" ...>Ir al sitio</a>
```

**Después (comportamiento esperado):**
- Ocultar el enlace `Ir al sitio`.
- Mostrar bloque de aviso en su lugar:

```
⚠ Acceso bloqueado
Sitio reportado como peligroso por VirusTotal.
Contacta a la entidad directamente por teléfono o correo electrónico.
```

El bloqueo se activa **solo después de que el usuario hace click en
"Revisar amenazas"** y el resultado es `suspicious` o `malicious`. Antes
de revisar, el botón "Ir al sitio" sigue visible (comportamiento actual
preservado para no romper el flujo nominal).

## Criterios de aceptación

- [ ] Certificado de prueba aparece en la tabla del catálogo.
- [ ] Click en "Revisar amenazas" de esa fila devuelve `suspicious` o
      `malicious` (depende de la respuesta real de VirusTotal).
- [ ] Tras revisar, el botón "Ir al sitio" desaparece y aparece el aviso
      de bloqueo con texto de contacto alternativo.
- [ ] Filas con resultado `safe` o `idle` **no** se ven afectadas.
- [ ] El catálogo sigue cargando sin depender de VT (no regresión
      de T-2026-04-17-03).

## Regla de no regresión

No modificar la lógica de `GET /api/v1/certificates` ni el flujo de
extracción de documentos. Solo afecta la columna Portal en la UI cuando
el resultado de threat-check ya fue obtenido.

## Nota para producción

El certificado de prueba debe eliminarse del catálogo antes de la
sustentación o marcarse con un flag `is_test = true` para filtrarlo en
la vista pública. Recomendado: eliminar con
`DELETE FROM certificates WHERE issuer ILIKE '%AMTSO%'` tras la validación.
