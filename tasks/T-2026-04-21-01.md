# T-2026-04-21-01 — Feature: lista de certificados mencionados pero no catalogados

**Estado:** completado — 2026-04-21
**Fecha creación:** 2026-04-21
**Asignado a:** LLM ejecutor (Claude Code / Codex)
**Relacionado con:** README §6, feature solicitada por usuario

## Objetivo

Cuando el usuario sube un documento, el sistema debe mostrar **también** los
certificados que fueron mencionados en el texto pero que **no existen en el
catálogo**. Estos se muestran sin link ni acciones, marcados como "no
verificable", para que el usuario no pierda la información extraída.

## Justificación

Hoy `matchCertificates` solo devuelve entradas del catálogo que coinciden con
`regex_patterns`. Si un documento menciona un certificado que no está en el
catálogo (p. ej. "certificado de supervivencia"), se pierde silenciosamente.
Esto contradice la propuesta de valor del portal.

## Alcance

**Incluye**
- Detección de menciones genéricas con regex de prefijos.
- Deduplicación y filtrado de los que ya hacen match con el catálogo.
- UI diferenciada para "no verificable" con badge y tooltip.
- Tests unitarios del matcher nuevo.

**No incluye**
- Backend no cambia.
- No se intenta adivinar el portal oficial ni enriquecer la entrada.
- No se persiste la detección — se muestra solo en la sesión actual.

## Criterios de aceptación

- [x] Documento de prueba con "certificado de supervivencia" detecta esa
      mención y la lista como no verificable.
- [x] Si el documento menciona "antecedentes judiciales" (ya en catálogo) y
      "paz y salvo predial" (no en catálogo), el primero aparece en la tabla
      principal como Encontrado y el segundo en la sección "Mencionados sin
      validar".
- [x] No se duplica nada entre ambas listas.
- [x] Tests unitarios cubren: detección, deduplicación, ausencia de
      menciones, normalización de tildes y mayúsculas.
- [x] README §6 actualizado con el nuevo flujo en 1-2 líneas.

## Pasos sugeridos

1. `frontend/src/utils/matcher.js` — añadir función
   `extractUnverifiedCertificates(text, matchedIds, catalog)` con patrones
   genéricos (`certificado de X`, `constancia de X`, `antecedentes de X`,
   `paz y salvo de X`, `carta de X`). Normaliza, deduplica, filtra los que
   ya hicieron match en catálogo.
2. Crear función consolidada `matchDocument(text, catalog)` que retorne
   `{ matched, unverified }` y reemplazar el uso actual de
   `matchCertificates` desde `DocumentUploader.jsx`.
3. `DocumentUploader.jsx` — cambiar `onExtracted(matches)` a
   `onExtracted({ matched, unverified })`.
4. `Extract.jsx` — guardar `unverifiedList` y pasarla a `CertificateTable`.
5. `CertificateTable.jsx` — añadir sección "Mencionados sin validar"
   debajo de la tabla principal, con filas sin columnas de portal ni
   amenazas, con badge "No verificable" y tooltip explicativo.
6. Extender `styles.css` con clases `cert-table__unverified-*` reutilizando
   variables existentes.
7. Añadir 3 tests a `matcher.test.js`: detección, deduplicación,
   normalización.
8. Actualizar README §6 con 2-3 líneas y RF-07 con el alcance extendido.
