# T-2026-04-21-02 — Feature: checklist de trazabilidad por certificado

**Estado:** completado — 2026-04-21
**Fecha creación:** 2026-04-21
**Asignado a:** LLM ejecutor
**Relacionado con:** RF-08 (tablero personal), feature solicitada por usuario

## Objetivo

Cada fila de la tabla de certificados (catalogados y no catalogados) debe
incluir un checkbox que el usuario puede marcar para llevar trazabilidad
personal de lo que ya gestionó. El estado persiste entre sesiones en el
mismo dispositivo.

## Justificación

El README ya tiene RF-08 como "deseable". Esta implementación lo satisface
en cliente, sin login, con trade-off explícito: no persiste entre
dispositivos, pero resuelve el 80% del valor con 20% del esfuerzo.

## Alcance

**Incluye**
- Persistencia en `localStorage` con key `certidoc.checklist`.
- Checkbox en filas de la tabla principal y en la sección "no verificable".
- Estilo visual para items completados (tachado, opacidad).
- Contador "N/M completados" visible en la página.
- Botón "Limpiar mi progreso" en header de la tabla.
- Test unitario del servicio con `localStorage` mockeado.

**No incluye**
- Persistencia en backend por usuario.
- Sincronización entre dispositivos.
- Historial de cambios.

## Criterios de aceptación

- [x] Marcar checkbox → fila muestra estilo "completado".
- [x] Recargar página → checkboxes marcados persisten.
- [x] Contador "3/12 completados" se actualiza en vivo.
- [x] Botón "Limpiar mi progreso" borra todo el estado con confirmación.
- [x] Test unitario cubre: get vacío, toggle, persistencia, limpieza.
- [x] README §3.1 RF-08 actualizado como "satisfecho con localStorage" y
      trade-off documentado.

   - `getChecklist()` — lee localStorage, retorna objeto.
   - `toggleItem(key)` — alterna y persiste.
   - `clearChecklist()` — borra la key.
   - Key interna: `cat:<id>` para certs del catálogo, `unv:<slug(label)>`
     para no verificables.
