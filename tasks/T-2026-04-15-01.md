# T-2026-04-15-01 — Simplificar procesamiento de archivos (PDF + imagen)

**Estado:** en progreso (parcial)
**Fase:** 4 — Procesamiento client-side (corrección)
**Dependencias:** T-2026-04-12-08

## Problema

Persisten fallos en extracción de PDF e integración de resultados de imagen:

- Error de worker PDF bloqueado por MIME `application/octet-stream`
- Error de seguridad al cargar worker OCR desde CDN
- Inestabilidad en `GET /api/v1/certificates` (502)
- Imágenes procesan, pero resultados no se ven en pantalla

## Cambios aplicados (iteración actual)

### frontend/src/components/DocumentUploader.jsx
- Se fortaleció validación de tipo de archivo con fallback por extensión (`.pdf/.jpg/.jpeg/.png/.txt`)
- Se unificó extracción local por tipo de archivo (texto, PDF, imagen)
- Se agregó `ensureCatalog()` para recargar catálogo cuando aún no está listo
- Se mantuvo barra de progreso visible desde el inicio con estado `Procesando...`

### frontend/src/services/pdf.js
- Se cambió `pdf.worker` de `?raw` a `?url`
- Se extrajo texto embebido por página con `getTextContent()`
- Fallback: si una página no trae texto, se renderiza a canvas y se aplica OCR solo a esa página

### frontend/src/services/ocr.js
- Se configuraron opciones explícitas de worker/core/lang para Tesseract
- Se agregaron fallbacks de inicialización (`spa` y luego fallback)
- Se sanitizó el error largo de `data:application/octet-stream;base64,...` para mostrar mensaje corto

## Validación reportada

- **Texto:** funciona y muestra resultados
- **Imagen:** procesa y se obtiene catálogo JSON en DevTools (respuesta con `items`), pero no se renderiza resultado en UI
- **PDF:** no funcional por bloqueo de worker/MIME

Errores observados:

- `Loading Worker ... blocked because of a disallowed MIME type (application/octet-stream)`
- `Content at http://localhost:5173/extract may not load data from https://cdn.jsdelivr.net/...`
- `GET /api/v1/certificates -> 502 Bad Gateway`

## Pendientes + posible solución corta

- [ ] **PDF bloqueado por MIME del worker**
  - Solución corta: servir `pdf.worker` local con MIME JavaScript correcto (`text/javascript`) desde `public/` o ajustar servidor/proxy para `.mjs`.

- [ ] **Bloqueo de seguridad para worker OCR CDN**
  - Solución corta: dejar de usar CDN en runtime; empaquetar worker/core de Tesseract localmente y cargar por ruta same-origin.

- [ ] **Imagen procesa pero no pinta resultados**
  - Solución corta: mostrar siempre sección de resultados (incluido `0 resultados`) y mensaje explícito cuando no hay matches; validar que `onExtracted(matches)` recibe array no vacío.

- [ ] **`/api/v1/certificates` intermitente (502)**
  - Solución corta: agregar reintento corto en frontend y revisar proxy/backend local antes de procesar archivo.

#### A1. PDF worker — servir local con MIME correcto

**Archivo:** `frontend/src/services/pdf.js`

- Copiar `node_modules/pdfjs-dist/build/pdf.worker.min.mjs` a `frontend/public/pdf.worker.min.mjs`
- Cambiar el import:
  ```js
  // ANTES
  import workerSrc from 'pdfjs-dist/build/pdf.worker.min.mjs?url'
  
  // DESPUÉS
  pdfjsLib.GlobalWorkerOptions.workerSrc = '/pdf.worker.min.mjs'
  ```
- Vite sirve archivos de `public/` con MIME correcto para `.mjs` (`text/javascript`)
- Eliminar el import `?url` que es la raíz del problema
- Agregar script `postinstall` en `package.json`:
  ```json

### Parte B: Reestructuración de UI — Vista unificada con tabla

#### Idea central

Fusionar `/extract` y `/catalog` en una sola página. La tabla del catálogo siempre visible. El uploader arriba. Al procesar un archivo, los certificados encontrados se resaltan en la tabla (fila destacada + badge) y se muestra resumen arriba.

**Flujo del usuario:**
1. Entra a la página → ve uploader arriba + tabla completa del catálogo abajo
2. Cada fila tiene indicador de "health" (si `portal_url` responde)
3. Sube archivo → se procesan matches
4. Tabla se reorganiza: matches arriba resaltados, resto del catálogo debajo
5. Si 0 matches: mensaje claro "No se encontraron certificados en el documento"

#### B1. Eliminar componentes que sobran

- **`CertificateList.jsx`** — se reemplaza por `CertificateTable.jsx`
- **`pages/Catalog.jsx`** — se absorbe en página unificada

#### B2. Nuevo componente: `CertificateTable.jsx`

**Responsabilidad:** tabla con catálogo completo, resaltado de matches, health status.

```

|--------|-------------|--------|--------|--------|--------|
| ★ Match| Cert. Nacim.| Regist.| 5 días | [Link] |  ● OK  |

**Funcionalidad:**

- Columnas: Estado (match/no-match), Nombre, Emisor, Tiempo estimado, Portal (link), Health
- Filas de matches arriba con clase CSS `.cert-table__row--match`
- Click en fila → expande detalle inline o navega a `/catalog/:id`

#### B3. Health check de portales

**Archivo:** nuevo `frontend/src/services/health.js`

- Función `checkPortalHealth(url)`: `fetch(url, { mode: 'no-cors', method: 'HEAD' })`
- `no-cors` + `HEAD` = verifica que responda (opaque response = OK, network error = DOWN)
- Se ejecuta al cargar tabla, en paralelo con `Promise.allSettled`
- Resultado en Map `url → 'ok' | 'error' | 'pending'`
- Indicador visual: punto verde/rojo/gris
