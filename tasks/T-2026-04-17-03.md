# T-2026-04-17-03 - Revision de amenazas bajo demanda (VirusTotal)

**Estado:** completada  
**Fase:** 4 - Seguridad + UX  
**Dependencias:** T-2026-04-17-01 (tabla unificada estable)

## Problema

La consulta de VirusTotal no puede bloquear la carga del catalogo. Si VT falla, falta API key o hay dependencia faltante, el usuario no debe perder la vista principal de certificados.

La directiva cambia a un modelo **bajo demanda**:

- El catalogo debe cargar rapido sin depender de VT.
- La revision de amenazas se dispara manualmente por fila.
- Si VT no responde, debe existir fallback funcional sin 500 ni caida del backend.

## Nuevo enfoque (objetivo)

1. `GET /api/v1/certificates` solo entrega catalogo (sin consulta VT en tiempo de carga).
2. La tabla agrega una columna final: `Revisar amenazas`.
3. Cada fila tiene boton `Revisar`.
4. Al hacer click, frontend envia el link/certificado al backend.
5. Backend consulta VT con timeout corto y responde estado para esa fila.
6. Si VT falla: responder `unavailable` (fallback), nunca romper flujo principal.

## Arquitectura propuesta

```
Usuario entra a /extract
        |
        v
GET /api/v1/certificates  (sin VirusTotal)
        |
        v
Tabla visible de inmediato
        |
click en "Revisar" por fila
        |
        v
POST /api/v1/certificates/{id}/threat-check
        |
        +--> VirusTotal OK      -> safe/suspicious/malicious
        |
        +--> VirusTotal falla   -> unavailable (fallback)
```
