# T-2026-04-12-03 — Auth y seguridad

**Estado:** completada
**Fase:** 1 — Backend core
**Dependencias:** T-2026-04-12-02

## Alcance

Implementar autenticación JWT, RBAC, rate limiting y honeypot.

## Auth

- POST /api/v1/auth/register — crea usuario con rol citizen
- POST /api/v1/auth/login — devuelve JWT con email, role, exp
- Middleware que extrae JWT del header Authorization
- bcrypt para hash de passwords (cost ≥ 12)
- JWT con expiración ≤ 1 hora
- Admin: se crea via seed o comando, no via registro público

## RBAC

| Rol | Acceso |
|---|---|
| público | GET /api/v1/certificates, POST /api/v1/extract, POST /api/v1/tickets |
| citizen | público |
| admin | citizen + /admin/* |

## Rate limiting

- Tickets: 1 por IP cada 24 horas
- Almacenado en tabla RateLimitEntry
- Respuesta HTTP 429 si excede

## Honeypot

- Campo oculto en formulario de tickets
- Si llega con valor, rechazar silenciosamente (HTTP 200 falso)

## Criterio de aceptación

- [x] Registro y login funcionales con JWT
- [x] Middleware rechaza acceso sin rol adecuado (HTTP 403)
- [x] Rate limit activo: segunda solicitud misma IP < 24h → 429
- [x] Honeypot implementado en endpoint de tickets
- [x] Passwords hasheados con bcrypt, nunca en texto plano
- [x] PEP 8, archivos ≤ 300 líneas, funciones ≤ 20 líneas
